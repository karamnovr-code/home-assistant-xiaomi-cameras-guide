# Камеры Xiaomi в Home Assistant через go2rtc

[English](README.md) | **Русский**

Практическая инструкция по подключению камер Xiaomi/Mi Home к Home Assistant,
созданию удобного мобильного просмотрщика, автозапуску живого видео,
масштабированию двумя пальцами и диагностике ошибок, которые встретились в
реальной установке.

Дата проверки: **19 сентября 2026 года**.

> go2rtc и его поддержка Xiaomi — сторонние community-компоненты. Поддерживаются
> не все модели. Не публикуйте логин Xiaomi, токены, DID, MAC/IP камер, названия
> комнат, конфигурацию со своими URL или кадры из дома.

## 1. Что было сделано

Рабочая схема получилась такой:

```text
Камера Xiaomi
  │ локальное видео + получение ключей через интернет
  ▼
go2rtc 1.9.14 как Home Assistant add-on
  │ Ingress с авторизацией Home Assistant
  ▼
один активный VideoRTC-плеер на карточку
  ├── автозапуск без звука
  ├── выбор камеры
  ├── полноэкранный режим
  ├── pinch-to-zoom вокруг точки касания
  └── остановка потока при закрытии карточки
```

В проверенной установке десять камер разных поколений воспроизводились через
внешний HTTPS Home Assistant. Две отключённые камеры с ошибкой `no-p2pid` были
временно убраны только из списка интерфейса. Запись, архив и детекция для
домашних Xiaomi-камер намеренно не включались.

## 2. Ограничения источника Xiaomi

Поддержка Xiaomi появилась в go2rtc 1.9.13. По документации upstream:

- поддерживаются новые `xiaomi/miss` и часть старых `xiaomi/legacy` камер;
- для получения ключей при каждом новом подключении нужен интернет;
- медиасоединение с камерой остаётся локальным;
- лучше всего работают камеры `miss` с P2P-протоколом `cs2`;
- старые `legacy`/`tutk` модели могут работать нестабильно;
- поддерживаются несколько аккаунтов, регионы, двухсторонний звук и две линзы,
  но совместимость зависит от модели.

Перед массовой настройкой проверьте одну камеру каждого модельного семейства.

## 3. Требования

- Home Assistant OS или Supervised для add-on и Supervisor Ingress;
- актуальная резервная копия Home Assistant;
- HACS только при использовании дополнительных карточек;
- аккаунт Xiaomi/Mi Home и доступ к подтверждению входа;
- камеры и Home Assistant в одной локальной сети;
- рабочий внешний HTTPS Home Assistant для удалённого просмотра;
- достаточно CPU, если понадобится перекодирование H.265 в H.264.

Ниже описан add-on-маршрут. Для Home Assistant Container/Core используйте
отдельный контейнер go2rtc и обычный защищённый reverse proxy; Supervisor Ingress
API там отсутствует.

## 4. Установка go2rtc add-on

1. Откройте **Settings → Apps → App store → ⋮ → Repositories**. В старых
   версиях Home Assistant раздел называется Add-ons.
2. Добавьте:

   ```text
   https://github.com/AlexxIT/hassio-addons
   ```

3. Установите **go2rtc**.
4. Включите автозапуск и запустите add-on.
5. Откройте Web UI через Ingress.
6. Проверьте журнал. Для версии 1.9.14 ожидаются слушатели API `:1984`, RTSP
   `:8554` и WebRTC `:8555` внутри подходящей сетевой схемы.

Не публикуйте `1984` в интернет. Для настройки Xiaomi достаточно Ingress. Если
LAN-доступ к `1984` всё же нужен другому локальному сервису, ограничьте его
локальной подсетью и не создавайте port-forward на роутере.

## 5. Вход Xiaomi и получение списка камер

1. В go2rtc откройте **Add → Xiaomi**.
2. Введите логин и пароль Xiaomi.
3. Введите код из SMS/e-mail и пройдите CAPTCHA, если Xiaomi их запросит.
4. Выберите правильный регион аккаунта.
5. Нажмите **load devices**.
6. Сохраните сгенерированные записи в конфигурацию go2rtc.

Upstream показывает структуру такого вида:

```yaml
xiaomi:
  "<XIAOMI_ACCOUNT_ID>": "<ENCRYPTED_OR_SESSION_VALUE>"

streams:
  living_room:
    - "xiaomi://<ACCOUNT_ID>:<REGION>@192.0.2.10?did=<DEVICE_ID>&model=<MODEL>"
```

Это только схема. Используйте точную строку, созданную Web UI для вашей камеры.
Не подменяйте `did`, `model` или регион догадкой.

## 6. Качество, линзы и `subtype`

В протоколе Xiaomi `miss` качество задаётся значением `0–5`. Обычно:

- `0` или `auto` — автоматический выбор;
- `1` или `sd` — низкое качество;
- `2` или `hd` — HD;
- у части новых моделей HD находится на другом номере;
- у старых моделей ручной высокий профиль может возвращать повреждённые
  параметры кодека.

Примеры:

```yaml
streams:
  camera_auto:
    - "xiaomi://<REDACTED>&subtype=auto"
  camera_sd:
    - "xiaomi://<REDACTED>&subtype=sd"
  dual_camera_second_lens:
    - "xiaomi://<REDACTED>&channel=2"
```

В нашей установке четыре камеры одного семейства начали стабильно открываться
после восстановления точного `model` и добавления `subtype=auto`. Не применяйте
это ко всем моделям автоматически — сначала сравните с URL, который выдал
go2rtc.

## 7. Сначала проверка одной камеры

Не добавляйте сразу десять потоков на панель. Для одной камеры проверьте:

1. поток появился на главной странице go2rtc;
2. WebRTC или MSE начинает воспроизведение;
3. `ffprobe` видит видео и, если ожидается, аудио;
4. разрешение и кодек соответствуют ожиданию;
5. поток работает не только кадром, а двигается 30–60 секунд;
6. после закрытия зрителя соединение с камерой освобождается;
7. проверка повторяется после перезапуска только add-on.

Пример локальной проверки без сохранения архива:

```bash
ffprobe -v error -show_streams \
  'rtsp://127.0.0.1:8554/living_room'
```

Для удалённой проверки используйте интерфейс Home Assistant, а не открытый RTSP
порт.

## 8. Почему не стоит запускать все камеры одновременно

Каждый активный плеер создаёт отдельное соединение, декодирование и сетевую
нагрузку. Xiaomi P2P также может ограничивать число одновременных сессий. В
первой неудачной карточке двенадцать потоков создавались одновременно. Это
усложняло диагностику, увеличивало задержку и оставляло тёмные плееры.

Рабочая компоновка:

- одна карточка для внутренних камер;
- один активный поток внутри карточки;
- выпадающий список и кнопки «назад/вперёд»;
- одна заранее выбранная стартовая камера;
- отдельная карточка внешних камер, если она нужна;
- потоки двух карточек независимы: переключение одной не останавливает другую;
- при закрытии раздела или popup плеер удаляется.

## 9. Ingress: причина `401 Unauthorized`

Прямой URL `/api/hassio_ingress/...` содержит временный контекст. Если сохранить
его в карточке и открыть после перезапуска приложения/браузера, часто возникает
`401 Unauthorized`.

В рабочем пользовательском компоненте сначала создавалась штатная Ingress-
сессия через WebSocket Home Assistant, устанавливалась cookie, затем запрашивался
актуальный `ingress_url` add-on:

```javascript
const session = await hass.callWS({
  type: "supervisor/api",
  endpoint: "/ingress/session",
  method: "post",
});

document.cookie = [
  `ingress_session=${session.session}`,
  "path=/api/hassio_ingress/",
  "SameSite=Strict",
  location.protocol === "https:" ? "Secure" : "",
].filter(Boolean).join(";");

const app = await hass.callWS({
  type: "supervisor/api",
  endpoint: "/addons/a889bffc_go2rtc/info",
  method: "get",
});

const base = app.ingress_url.replace(/\/$/, "");
```

`a889bffc_go2rtc` — публичный slug репозитория/add-on, а не приватный ID дома.
Тем не менее slug может измениться в другой сборке; читайте его из фактической
информации add-on.

Этот API ориентирован на HAOS/Supervised и не является универсальным публичным
контрактом для произвольных веб-приложений. После обновления Home Assistant его
нужно перепроверять. Если готовая карточка умеет работать с go2rtc через Home
Assistant без ручной Ingress-сессии, предпочитайте её.

## 10. Загрузка VideoRTC и автозапуск

После получения актуального `base` можно загрузить компонент из самого go2rtc:

```javascript
const { VideoRTC } = await import(`${base}/video-rtc.js`);

class XiaomiLivePlayer extends VideoRTC {
  oninit() {
    super.oninit();
    this.video.muted = true;
    this.video.autoplay = true;
    this.video.playsInline = true;
    this.video.style.objectFit = "contain";
  }
}
```

Автозапуск на iOS и Chromium надёжнее при `muted=true`. Звук включайте отдельной
кнопкой после действия пользователя. Не создавайте сразу несколько элементов
для одной карточки.

При смене камеры:

1. увеличьте внутренний номер поколения запроса;
2. удалите старый плеер;
3. создайте новый с выбранным именем потока;
4. игнорируйте поздние ответы старого запроса;
5. покажите понятное состояние «подключение», «нет связи» или «снимок».

При закрытии:

```javascript
stop() {
  clearInterval(this.sessionTimer);
  clearTimeout(this.checkTimer);
  this.player?.remove();
  this.player = null;
}
```

Именно удаление плеера, а не скрытие CSS, прекращает лишний поток.

## 11. Продление Ingress-сессии

Долгий просмотр может пережить срок сессии. В рабочей реализации сессия
периодически проверялась:

```javascript
this.sessionTimer = setInterval(() => {
  hass.callWS({
    type: "supervisor/api",
    endpoint: "/ingress/validate_session",
    method: "post",
    data: { session: session.session },
  }).catch(() => this.showReconnectMessage());
}, 60_000);
```

Не запускайте несколько таймеров при каждом переключении камеры. Всегда очищайте
предыдущий таймер.

## 12. Масштабирование вокруг точки касания

Обычный `transform: scale()` увеличивает только центр. Для увеличения выбранной
точки пересчитывайте смещение:

```javascript
function zoomAt(nextScale, focusX, focusY) {
  const next = Math.max(1, Math.min(8, nextScale));
  const ratio = next / scale;
  panX = focusX - (focusX - panX) * ratio;
  panY = focusY - (focusY - panY) * ratio;
  scale = next;
  paint();
}
```

Для двух пальцев храните активные `PointerEvent`:

- расстояние между точками меняет масштаб;
- центр двух точек задаёт фокус;
- движение центра меняет `panX/panY`;
- при одном пальце и `scale > 1` выполняется панорамирование;
- `touch-action: none` нужен только внутри видеообласти;
- ограничивайте смещение, чтобы изображение нельзя было полностью увести за
  экран.

Полноэкранный режим должен переносить тот же DOM-узел плеера, а не создавать
второй поток. После закрытия верните его в карточку и сохраните жесты.

## 13. Кодеки и совместимость браузера

Часть Xiaomi-камер отдаёт H.265, PCMA или комбинации, которые браузер не может
проиграть напрямую. В одной проверке H.265-видео успешно декодировалось в
изображение полного разрешения, а аудиопакеты PCMA приходили, но слышимость в
браузере отдельно не подтверждалась.

Если go2rtc видит поток, а браузер показывает тёмный экран:

1. откройте `api/streams` и проверьте фактические кодеки;
2. проверьте тот же поток через `ffprobe`;
3. сначала попробуйте другой transport VideoRTC/MSE;
4. добавьте **on-demand** совместимый H.264/AAC источник только для проблемной
   камеры;
5. измерьте CPU до массового перекодирования.

Не включайте постоянное перекодирование всех камер. Это увеличивает задержку и
нагрузку даже тогда, когда никто не смотрит видео.

## 14. Реальные ошибки и исправления

### Web UI зависает на `Loading…`

Проверьте отдельно:

```text
/
/main.js
/add.html
/api
/api/streams
```

Для каждого запроса зафиксируйте HTTP status, `Content-Type` и реальное тело.
Затем откройте Network/Console браузера и найдите первый сломавшийся ресурс.
Проверяйте локальный HA и внешний HTTPS отдельно. Переустановка go2rtc до этой
диагностики обычно не помогает.

### Свежий браузер получает `401`

Причина: сохранён старый Ingress URL или отсутствует текущая Ingress-сессия.

Исправление: создавать и проверять сессию перед загрузкой VideoRTC, получать
актуальный `ingress_url`, не хранить токенизированный путь в YAML.

### Плеер тёмный, но spinner не исчезает

Проверьте поток в go2rtc и `ffprobe`, затем кодеки браузера. Также убедитесь, что
параметры `model`, `did`, регион и `subtype` не были потеряны при ручном
копировании URL.

### `no-p2pid`

Эта ошибка встречалась у двух фактически отключённых камер. Возможные причины:

- камера офлайн;
- модель или прошивка не поддерживается;
- Xiaomi не выдал P2P ID/ключ;
- неверный регион, аккаунт, `did` или `model`;
- достигнут лимит сессий.

Не создавайте бесконечный цикл переподключения. Уберите камеру из пользовательского
списка, сохранив конфигурацию, и верните после отдельной проверки.

### Камера заработала только с `subtype=auto`

У некоторых моделей ручной высокий профиль возвращал некорректные параметры
кодека. Верните строку из go2rtc UI и попробуйте `subtype=auto` только на
проблемном модельном семействе.

### Двенадцать камер не воспроизводятся одновременно

Причина: слишком много P2P-сессий, декодеров и DOM-плееров. Перейдите на один
выбираемый поток. Для двух независимых карточек создайте два независимых
экземпляра с разными таймерами и состоянием.

### После «оптимизации» видео стало тормозить

В нашем случае эксперимент с уменьшенным потоком и пилотом записи ухудшил
восприятие живого видео. Мы вернули исходный поток, естественную скорость,
полное качество и отказались от постоянной записи. Меняйте только один параметр,
сравнивайте время/кадры/разрешение и сохраняйте исходный URL.

### Звук не включается автоматически

Это ограничение autoplay браузера. Стартуйте без звука и включайте звук после
явного нажатия. Одновременно проверьте, что аудиокодек вообще поддерживается.

### Прямой поток работает, а внешний Home Assistant нет

Причина находится в Ingress-сессии, cookie, HTTPS, reverse proxy или ресурсных
URL, а не в самой камере. Сравните HTML, JavaScript, API и WebSocket/RTC-запросы
на локальном и внешнем маршруте.

## 15. Архив на SD-карте и запись

Список живых камер Xiaomi в go2rtc не означает доступ к архиву на внутренней
SD-карте. В проверенной схеме архив Xiaomi Home не был подключён к Home
Assistant.

Перед серверной записью измерьте одну камеру минимум 15–60 минут в типичных
дневных и ночных условиях. Один короткий пилот дал ориентир около **39,7 ГБ на
72 часа** для конкретного потока. Это не универсальная норма: битрейт камеры,
движение, аудио и перекодирование меняют объём.

Формула:

```text
объём_за_сутки_ГБ = средний_битрейт_Мбит_с × 10,8
```

Добавьте 20–30% резерва и отдельно измерьте CPU/RAM. Для записи и детекции лучше
использовать Frigate или другой NVR отдельным проектом. Не смешивайте подключение
живого видео, запись и AI-детекцию в одно изменение.

## 16. Приёмочная проверка

На мобильном viewport и реальном телефоне проверьте:

- [ ] стартовая камера запускается автоматически без нажатия «Смотреть»;
- [ ] видео движется, а не показывает один кадр;
- [ ] разрешение соответствует выбранному качеству;
- [ ] переключение камеры останавливает старый поток;
- [ ] две карточки, если они есть, работают независимо;
- [ ] pinch-to-zoom увеличивает точку под пальцами;
- [ ] панорамирование работает после увеличения;
- [ ] полноэкранный режим сохраняет поток и жесты;
- [ ] закрытие раздела оставляет ноль активных видеоплееров;
- [ ] повторное открытие снова запускает стартовую камеру;
- [ ] истёкшая Ingress-сессия показывает понятную кнопку переподключения;
- [ ] отключённая камера не создаёт бесконечные запросы;
- [ ] внешний HTTPS и локальный маршрут дают одинаковый результат;
- [ ] другие панели Home Assistant и Frigate не изменились.

## 17. Откат

Перед изменением сохраните:

- конфигурацию go2rtc;
- исходный ресурс JavaScript карточки;
- JSON/YAML панели;
- список потоков и контрольные суммы файлов;
- скриншот/текст ожидаемого поведения без кадров из дома.

Откат:

1. верните предыдущий JS-ресурс и URL версии ресурса;
2. верните предыдущую карточку панели;
3. восстановите только изменённые записи `streams`;
4. перезапустите go2rtc только если менялась его конфигурация;
5. не перезапускайте весь Home Assistant без необходимости;
6. повторите тест одного потока и проверку остальных панелей.

## 18. Что нельзя публиковать

- логин, пароль и код подтверждения Xiaomi;
- блок `xiaomi:` из рабочей конфигурации;
- полные `xiaomi://` URL;
- DID, MAC, IP, serial и model-to-home mapping;
- имена людей, комнат и дома;
- кадры, на которых видны люди, интерьер, двор или адрес;
- Ingress URL, Home Assistant token и внешний личный hostname;
- приватный dashboard JSON или JavaScript с реальными entity ID.

В публичных примерах используйте `living_room`, `camera_a`, `192.0.2.10`,
`<DEVICE_ID>` и `<REDACTED>`.
